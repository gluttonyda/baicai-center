# Baicai-Center 整改执行单

## 说明

- 本执行单对应当前运行中的 `baicai-center` 项目。
- 生产目录保持不动，后续整改与验证仅在测试目录内进行：`/opt/baicai-center/_test_mod`
- 当前部署前提为：`单 Center + 多 Worker`

## 目标

- 先修复影响数据正确性、状态一致性和安全性的关键问题。
- 不改变现网运行目录，所有代码整改先在测试副本完成。
- 整改后补充最小可回归测试与验证步骤。

## 当前状态快照

- 当前整改与验证范围仅限测试目录：`/opt/baicai-center/_test_mod`

## 分文件整改清单

### 1. `main.py`

#### P0

- 将 `API_TOKEN`、MySQL 主机、用户名、密码改为环境变量读取。
- 收紧 `worker_registry` 注册逻辑，不再完全信任客户端上报的 `worker_api_url`。
- 所有下发 Worker 的 `httpx.post()` 补 `raise_for_status()`。
- 拆分 `dispatch_locked_until` 与 `quota_blocked_until`。
- 将“清理触发条件”改为硬安全挡板 + 软策略等待。

#### P1

- 在 `/api/report_status` 增加 `uploading` 心跳处理，刷新节点活跃时间。
- 为 `status`、`upload_method`、`worker_node`、`files` 增加输入校验。
- 区分上传失败与清道夫失败，避免误回退 `staged` 状态。

#### P2

- 梳理调度阶段的事务边界，降低定时器重入造成的状态漂移。
- 增加结构化日志字段：`node_name`、`account_name`、`task_count`、`status_code`。

#### 验收

- Worker 返回 `500`
- Worker 返回 `401`
- 长任务超过 `15` 分钟
- 未知 `status`
- 清道夫失败后再次调度
- `force_all=True` 不得绕过“同组仍在上传”的保护
- 全组 quota 耗尽后应立即允许清理

### 2. `worker.py`

#### P0

- 将“本地 0 文件命中即 completed”改为失败或专用状态。
- 对收到的相对路径做 `normpath` 校验，防止 `../` 越界。

#### P1

- 限制 `upload_method` 允许值。
- `report_status()` 对非 2xx 响应视为失败并重试。
- `task_router()` 兜底异常后上报 `failed`。

#### P2

- 优化成功文件提取逻辑，降低对 rclone 自由文本日志的依赖。
- 清理上传与清道夫日志输出策略，保留摘要和明细两层日志。

#### 验收

- 非法路径
- 非法 `upload_method`
- Center 返回 `500`
- rclone 异常退出

### 3. `scanner.py`

#### P1

- 去掉裸 `except`，按异常类型记录错误。
- 增加每轮扫描统计日志：
  - 扫描总数
  - 过滤后数量
  - 未到延迟时间数量
  - 已缓存跳过数量
  - 实际上报数量

#### P2

- 将 `unicodedata` 调整为模块级导入。
- 视情况增加 SQLite `busy_timeout` / WAL 配置。
- 按 `/data/links` 与 `/data/rclone-cache` 分别输出摘要日志。

#### 验收

- 权限错误文件
- 一小时内新文件
- Unicode/NFC 路径

### 4. `init_sync.py`
