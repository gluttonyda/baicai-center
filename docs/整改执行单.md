# 整改记录

本文档记录 Baicai Center 当前版本已经完成的关键整改。

## 配置整改

- 敏感配置统一从环境变量读取
- 根目录提供 `.env.example`
- Worker 目录提供 `baicai-work/.env.example`
- 真实 `.env` 已通过 `.gitignore` 排除
- Worker 白名单通过 `WORKER_API_URL_MAP` 控制

## Center 整改

- 增加请求字段校验
- 增加 Worker 地址校验
- 增加 Worker 白名单机制
- 增加上传任务心跳处理
- 增加调度失败回滚
- 增加即时重调度触发
- 拆分账号锁：
  - `dispatch_locked_until`
  - `quota_blocked_until`

## Worker 整改

- 增加路径越界校验
- 增加本地缺失文件回报
- 增加状态上报重试
- 长任务周期性回报 `uploading`
- 上传命令使用 `--drive-stop-on-upload-limit`
- uploader 非零退出码统一按 `403_quota` 处理
- cleaner 和 uploader 都通过标准输出记录日志

## Scanner 整改

- 扫描目录通过环境变量配置
- 增加 SQLite 本地缓存
- 增加稳定性判断，避免搬运仍在写入的缓存文件
- 增加扫描摘要日志
- 支持按批量上报 Center

## Init Sync 整改

- 历史同步改为流式分块提交
- 失败批次可落盘
- `WORKER_NODE_NAME` 明确要求使用 `Init_Scanner`
- 用于建立目标盘防重复屏障

## Cleaner 策略整改

Cleaner 现在遵守以下规则：

- 同组存在 `uploading` 时绝不清理
- 同组 uploader 全部 quota blocked 时立即清理
- 否则等待 `CLEANER_IDLE_MINUTES` 空闲窗口

`force_all=True` 只能绕过软等待条件，不能绕过同组上传安全挡板。

## 测试整改

已建立回归测试覆盖：

- Center API 状态流转
- uploader 调度
- cleaner 调度
- quota 封禁
- credential invalid
- Worker API
- scanner 缓存与扫描
- init sync 分块提交
- Worker 本地 rclone 往返链路

当前测试命令：

```bash
PYTHONPATH=.:baicai-work pytest -q
```

## 公开仓库整改

- 新增 `.gitignore`
- 新增 `.dockerignore`
- 示例配置替换为占位值
- 真实节点名、真实公网地址和真实目标目录名已从 tracked 文件中移除
- 数据库备份、日志、重复文件清单和运行缓存不进入公开仓库
