# 配置任务清单

这是从零部署 Baicai Center 时的检查清单。

## 1. 公共准备

- 准备一个足够随机的 `API_TOKEN`
- 为每个 Worker 及历史同步节点分别准备随机 `NODE_TOKEN`，保持机器时钟同步
- 准备 MySQL 8.x 数据库
- 准备 Center 对外地址
- 准备每台 Worker 对 Center 可访问的地址
- 准备每台 Worker 的 `rclone.conf`
- 确认目标 Google Drive 目录名称

## 2. Center 配置

复制模板：

```bash
cp .env.example .env
```

必填：

```text
API_TOKEN
DB_HOST
DB_USER
DB_PASSWORD
DB_NAME
WORKER_API_URL_MAP
WORKER_TOKEN_MAP
```

常用调度参数：

```text
MAX_FILES_PER_REQUEST
MAX_SUCCESSFUL_FILES
MAX_MISSING_FILES
MAX_CLEANER_FILES_PER_REQUEST
CLEANER_IDLE_MINUTES
CLEANER_DISPATCH_INTERVAL_MINUTES
WORKER_STALE_MINUTES
ACCOUNT_DISPATCH_LEASE_MINUTES
UPLOADING_STALE_MINUTES
QUOTA_BLOCK_HOURS
MAX_CONCURRENT_UPLOADS_PER_WORKER_DAY
MAX_CONCURRENT_UPLOADS_PER_WORKER_NIGHT
```

`WORKER_API_URL_MAP` 示例：

```json
{"worker-node-1":"http://worker-node-1.example.com:8001/task/upload"}
```

如果这个值非空，Center 只接受白名单里的 Worker。留空时 Center 会信任并请求节点上报的地址，生产环境应配置完整白名单。

`HISTORY_SYNC_NODE_NAMES` 默认 `Init_Scanner`，只有名单内的签名节点可以提交历史同步。

`WORKER_TOKEN_MAP` 按相同节点名填写对应的独立 `NODE_TOKEN`。默认使用 HMAC，保持 `ALLOW_LEGACY_NODE_AUTH=false`、`ALLOW_LEGACY_UNLEASED_REPORTS=false`。

## 3. 数据库

新库导入：

```bash
mysql -h "$DB_HOST" -u "$DB_USER" -p"$DB_PASSWORD" "$DB_NAME" < SCHEMA_MINIMAL.sql
```

旧库先备份、停止 Center 与 Scanner，再按顺序执行四项迁移：

```bash
mysql -h "$DB_HOST" -u "$DB_USER" -p"$DB_PASSWORD" "$DB_NAME" < MIGRATION_SPLIT_ACCOUNT_LOCKS.sql
mysql -h "$DB_HOST" -u "$DB_USER" -p"$DB_PASSWORD" "$DB_NAME" < MIGRATION_UPLOAD_USAGE_STATS.sql
mysql -h "$DB_HOST" -u "$DB_USER" -p"$DB_PASSWORD" "$DB_NAME" < MIGRATION_DISPATCH_PROTOCOL_V2.sql
mysql -h "$DB_HOST" -u "$DB_USER" -p"$DB_PASSWORD" "$DB_NAME" < MIGRATION_FILE_PATH_HASH.sql
```

`MIGRATION_FILE_PATH_HASH.sql` 发现重复 `file_path`、不兼容的已有 `file_path_hash` 列或该列的前缀/表达式唯一索引时会终止且不改数据，按 [Center 节点说明](center_node.md#file_path_hash-迁移) 人工处理后重跑。

新库当前最小结构已包含这些变更。请使用当前版本的迁移脚本，它们检查已有字段和索引，不自动回填历史封禁状态。

确认 `drive_accounts` 有这些字段：

```text
dispatch_locked_until
dispatch_cooldown_until
quota_blocked_until
current_dispatch_id
current_worker_node
```

还需确认 `file_tasks` 的来源目录、大小、修改时间和 `dispatch_id`，`worker_registry.protocol_version`，以及 `account_upload_events.dispatch_id`；最终以 `/health/ready` 检查必要字段。

如果旧表里使用过 `cooldown_until`，不要自动迁移历史锁。需要人工判断旧值是短期调度锁还是 quota 封禁。

## 4. 账号池

需要准备：

- uploader 账号
- cleaner 账号
- uploader 到 cleaner 的映射

账号组默认按 `@` 前缀判断。例如：

```text
example_1@1 -> example_1
example_1@2 -> example_1
```

同组 uploader 仍在上传时，cleaner 不会清理。

## 5. 历史同步

如果目标盘已有文件，先运行：

```bash
python init_sync.py
```

执行前设置：

```text
WORKER_NODE_NAME=Init_Scanner
RCLONE_REMOTE_ACCOUNT=your-rclone-remote
TARGET_DIR=your-target-dir
NODE_TOKEN=CHANGE_ME_WITH_INIT_SCANNER_TOKEN
```

不要使用真实 Worker 节点名运行 `init_sync.py`。Center 的 `WORKER_TOKEN_MAP` 中添加 `Init_Scanner` 的独立密钥；URL 白名单启用时也添加同名地址条目。

## 6. Worker 配置

进入 Worker 目录：

```bash
cd baicai-work
cp .env.example .env
```

必填：

```text
NODE_TOKEN
CENTER_URL
CENTER_API
WORKER_NODE_NAME
WORKER_API_URL
TARGET_REMOTE_DIR
ALLOWED_BASE_DIRS
```

`API_TOKEN` 只在 `ALLOW_LEGACY_BEARER_AUTH=true` 或 `SCANNER_SEND_BEARER_AUTH=true` 时必填，且须与 Center 一致。

Scanner 参数：

```text
SCANNER_CHUNK_SIZE
LINKS_DELAY_HOURS
CACHE_LINKS_DELAY_HOURS
RCLONE_CACHE_DELAY_HOURS
RCLONE_CACHE_STABLE_SECONDS
SCANNER_LOOP_SECONDS
CACHE_DB_PATH
LINKS_SCAN_DIR
CACHE_LINKS_SCAN_DIR
RCLONE_CACHE_SCAN_DIR
```

并发参数：

```text
MAX_CONCURRENT_UPLOADS_PER_WORKER_DAY
MAX_CONCURRENT_UPLOADS_PER_WORKER_NIGHT
MAX_CONCURRENT_CLEANERS_PER_WORKER
RCLONE_TRANSFERS
RCLONE_CHECKERS
```

旧单值上传并发参数已被替代。Center 与 Worker 保持相同昼夜值，默认白天 2 路、北京时间 01:00–10:00 为夜间 3 路。

配置持久化 `TASK_JOURNAL_DB_PATH=/opt/baicai-worker/runtime/task_journal.db` 和 `REPORT_RETRY_INTERVAL_SECONDS`，保留 `runtime/` 以便重启恢复任务、补送最终回执。

## 7. Worker 目录

确认目录存在：

```text
/data/links
/cache/links
/data/rclone-cache
baicai-work/logs/rclone
baicai-work/runtime
```

三个扫描根采用宿主机绝对路径挂载；前两项上报 `copy`，第三项上报 `move`。修改路径时同步 Compose、Scanner 的 `*_SCAN_DIR` 和 `ALLOWED_BASE_DIRS`。

确认宿主机有：

```text
/root/.config/rclone/rclone.conf
/usr/bin/rclone
```

## 8. 启动

Center：

```bash
docker compose up -d --build
```

Worker：

```bash
cd baicai-work
docker compose up -d --build
```

## 9. 启动后验证

Center：

```bash
curl --fail http://127.0.0.1:8080/health/ready
```

Worker：

```bash
cd baicai-work
docker compose ps
docker compose logs -f worker-api
docker compose logs -f scanner
```

## 10. 重置后的处理

如果 Center 的 `file_tasks` 被清空或重建，先停止各节点 Scanner 并备份扫描缓存，再清理缓存以便全量重报：

```bash
rm -f baicai-work/runtime/scanner_cache.db
```

否则 scanner 会认为文件已经上报过。普通重启无需清理缓存；不要删除任务 journal 或整个 `runtime/`，未完成派发和未送达回执保存在其中。

## 11. 上 GitHub 前检查

不要提交：

```text
.env
baicai-work/.env
rclone.conf
db-backups/
backups/
logs/
runtime/
duplicate_*.txt
dedupe_*.log
```

检查命令：

```bash
git status --short --ignored
git add --dry-run .
```
