# 配置任务清单

## 当前检查结论

- 生产目录 `docker-compose.yml` 依赖根目录 `.env`
- 当前生产目录未发现 `.env` 或 `.env.example`
- 新代码已改为严格读取环境变量，若缺少关键变量，服务启动会直接失败
- 数据库字段迁移脚本 `MIGRATION_SPLIT_ACCOUNT_LOCKS.sql` 已就位，但是否已执行仍需人工确认

## 必做项

### 1. 创建生产 `.env`

- 在 `/opt/baicai-center/.env` 创建配置文件
- 不要把测试值直接写入生产 `.env`
- 建议先从测试副本里的两个模板合并出生产版

### 2. 配置 Center 必填变量

- `API_TOKEN`
- `DB_HOST`
- `DB_USER`
- `DB_PASSWORD`
- `DB_NAME`

### 3. 配置 Center 调度相关变量

- `WORKER_API_URL_MAP`
- `MAX_FILES_PER_REQUEST`
- `MAX_SUCCESSFUL_FILES`
- `MAX_MISSING_FILES`
- `MAX_CLEANER_FILES_PER_REQUEST`
- `CLEANER_IDLE_MINUTES`
- `WORKER_STALE_MINUTES`
- `ACCOUNT_DISPATCH_LEASE_MINUTES`
- `QUOTA_BLOCK_HOURS`

### 4. 配置 Worker 运行相关变量

- `CENTER_URL`
- `TARGET_REMOTE_DIR`
- `ALLOWED_BASE_DIRS`

说明：

- 如果 `worker.py` 与 `scanner.py` 在同一节点运行，二者会共用 `API_TOKEN`
- `ALLOWED_BASE_DIRS` 建议与真实挂载目录一致

### 5. 配置 Scanner 相关变量

- `CENTER_API`
- `WORKER_NODE_NAME`
- `WORKER_API_URL`
- `CACHE_DB_PATH`
- `SCANNER_CHUNK_SIZE`
- `LINKS_DELAY_HOURS`
- `RCLONE_CACHE_DELAY_HOURS`

### 6. 配置 Init Sync 相关变量

- `RCLONE_REMOTE_ACCOUNT`
- `TARGET_DIR`
- `INIT_SYNC_CHUNK_SIZE`
- `FAILED_CHUNKS_DIR`

重要说明：

- 执行 `init_sync.py` 时，`WORKER_NODE_NAME` 必须临时改为 `Init_Scanner`
- 不得使用任何真实 Worker 节点名执行 `init_sync.py`

### 7. 执行数据库字段迁移

- 执行 `MIGRATION_SPLIT_ACCOUNT_LOCKS.sql`
- 确认 `drive_accounts` 新增字段：
  - `dispatch_locked_until`
  - `quota_blocked_until`
- 确认相关索引已建立

### 8. 人工确认旧锁状态

- 旧 `cooldown_until` 历史上混用了调度锁和 quota 封禁
- 若要保留旧状态，需要人工判断并回填：
  - 短期执行锁写入 `dispatch_locked_until`
  - 已确认 quota 封禁写入 `quota_blocked_until`

### 9. 重建防重与扫描状态

- 如果重置过 `file_tasks`，先执行 `python init_sync.py`
- 然后在每个 Worker 节点删除本地扫描缓存：
  - `/opt/baicai-worker/scanner_cache.db`

### 10. 启动前自检

- 确认 `.env` 已被 `docker-compose.yml` 正确引用
- 确认 `WORKER_API_URL_MAP` 是合法 JSON
- 确认 `CENTER_API`、`CENTER_URL`、`WORKER_API_URL` 都是完整 URL
- 确认 `CACHE_DB_PATH` 所在目录可写
- 确认目标 `rclone` 账号与远端目录名称正确

### 11. 启动后验证

- 验证 Center 根接口可访问
- 验证容器健康检查通过
- 验证 Worker 能正常上报心跳
- 验证 `tests/` 回归可继续运行
- 验证清道夫策略符合新规则：
  - 同组上传活跃时绝不清
  - 全组 quota 耗尽时立即清
  - 否则按空闲窗口清理

## 推荐执行顺序

1. 创建并填写 `.env`
2. 执行数据库迁移
3. 人工处理旧锁状态
4. 如有需要执行 `init_sync.py`
5. 清理 Worker 扫描缓存
6. 启动 Center
7. 检查健康状态与日志
8. 做一轮小规模联调

## 目前发现的直接风险

- 缺少生产 `.env`：当前 `docker-compose.yml` 无法按新代码直接稳定启动
- 未确认迁移是否已执行：若代码已切换但表结构未更新，`main.py` 会在运行时因字段不存在而失败
