# 配置任务清单

这是从零部署 Baicai Center 时的检查清单。

## 1. 公共准备

- 准备一个足够随机的 `API_TOKEN`
- 准备 MySQL 8.x 数据库
- 准备 Center 对外地址
- 准备每台 Worker 对 Center 可访问的地址
- 准备每台 Worker 的 `rclone.conf`
- 确认目标 Google Drive 目录名称

## 2. Center 配置

复制模板：

```bash
cp .env.example .env
```

必填：

```text
API_TOKEN
DB_HOST
DB_USER
DB_PASSWORD
DB_NAME
WORKER_API_URL_MAP
```

常用调度参数：

```text
MAX_FILES_PER_REQUEST
MAX_SUCCESSFUL_FILES
MAX_MISSING_FILES
MAX_CLEANER_FILES_PER_REQUEST
CLEANER_IDLE_MINUTES
CLEANER_DISPATCH_INTERVAL_MINUTES
WORKER_STALE_MINUTES
ACCOUNT_DISPATCH_LEASE_MINUTES
UPLOADING_STALE_MINUTES
QUOTA_BLOCK_HOURS
```

`WORKER_API_URL_MAP` 示例：

```json
{"worker-node-1":"http://worker-node-1.example.com:8001/task/upload"}
```

如果这个值非空，Center 只接受白名单里的 Worker。

## 3. 数据库

新库导入：

```bash
mysql -h "$DB_HOST" -u "$DB_USER" -p"$DB_PASSWORD" "$DB_NAME" < SCHEMA_MINIMAL.sql
```

旧库升级：

```bash
mysql -h "$DB_HOST" -u "$DB_USER" -p"$DB_PASSWORD" "$DB_NAME" < MIGRATION_SPLIT_ACCOUNT_LOCKS.sql
```

确认 `drive_accounts` 有这些字段：

```text
dispatch_locked_until
quota_blocked_until
```

如果旧表里使用过 `cooldown_until`，不要自动迁移历史锁。需要人工判断旧值是短期调度锁还是 quota 封禁。

## 4. 账号池

需要准备：

- uploader 账号
- cleaner 账号
- uploader 到 cleaner 的映射

账号组默认按 `@` 前缀判断。例如：

```text
example_1@1 -> example_1
example_1@2 -> example_1
```

同组 uploader 仍在上传时，cleaner 不会清理。

## 5. 历史同步

如果目标盘已有文件，先运行：

```bash
python init_sync.py
```

执行前设置：

```text
WORKER_NODE_NAME=Init_Scanner
RCLONE_REMOTE_ACCOUNT=your-rclone-remote
TARGET_DIR=your-target-dir
```

不要使用真实 Worker 节点名运行 `init_sync.py`。

## 6. Worker 配置

进入 Worker 目录：

```bash
cd baicai-work
cp .env.example .env
```

必填：

```text
API_TOKEN
CENTER_URL
CENTER_API
WORKER_NODE_NAME
WORKER_API_URL
TARGET_REMOTE_DIR
ALLOWED_BASE_DIRS
```

Scanner 参数：

```text
SCANNER_CHUNK_SIZE
LINKS_DELAY_HOURS
RCLONE_CACHE_DELAY_HOURS
RCLONE_CACHE_STABLE_SECONDS
SCANNER_LOOP_SECONDS
CACHE_DB_PATH
```

并发参数：

```text
MAX_CONCURRENT_UPLOADS_PER_WORKER
MAX_CONCURRENT_CLEANERS_PER_WORKER
```

## 7. Worker 目录

确认目录存在：

```text
baicai-work/links
baicai-work/rclone-cache
baicai-work/logs/rclone
baicai-work/runtime
```

确认宿主机有：

```text
/root/.config/rclone/rclone.conf
```

## 8. 启动

Center：

```bash
docker compose up -d --build
```

Worker：

```bash
cd baicai-work
docker compose up -d --build
```

## 9. 启动后验证

Center：

```bash
curl http://127.0.0.1:8080/
```

Worker：

```bash
cd baicai-work
docker compose ps
docker compose logs -f worker-api
docker compose logs -f scanner
```

## 10. 重置后的处理

如果 Center 的 `file_tasks` 被清空或重建，需要在每个 Worker 删除扫描缓存：

```bash
rm -f baicai-work/runtime/scanner_cache.db
```

否则 scanner 会认为文件已经上报过。

## 11. 上 GitHub 前检查

不要提交：

```text
.env
baicai-work/.env
rclone.conf
db-backups/
backups/
logs/
runtime/
duplicate_*.txt
dedupe_*.log
```

检查命令：

```bash
git status --short --ignored
git add --dry-run .
```
