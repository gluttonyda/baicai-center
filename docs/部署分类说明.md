# 部署分类说明

本仓库包含 Center 和 Worker 两部分。

部署时不需要把整个仓库原样放到每台机器上。推荐做法是：

- Center 节点使用仓库根目录
- Worker 节点使用 `baicai-work/` 目录

## Center 节点

Center 是主控大脑，需要数据库和网络出口，负责调度所有 Worker。

Center 需要的文件：

```text
main.py
init_sync.py
Dockerfile
docker-compose.yml
requirements.txt
SCHEMA_MINIMAL.sql
MIGRATION_SPLIT_ACCOUNT_LOCKS.sql
scripts/
docs/
.env.example
```

Center 不需要：

```text
baicai-work/worker.py
baicai-work/scanner.py
Worker 本地媒体目录
Worker runtime 缓存
```

## Worker 节点

Worker 是执行节点，需要本地文件目录、rclone 配置和能被 Center 访问的 HTTP 地址。

Worker 需要的文件：

```text
baicai-work/worker.py
baicai-work/scanner.py
baicai-work/scanner-loop.sh
baicai-work/Dockerfile
baicai-work/docker-compose.yml
baicai-work/requirements.txt
baicai-work/.env.example
```

Worker 不需要：

```text
main.py
init_sync.py
Center MySQL 账号
数据库维护脚本
```

## 多地区部署模型

```text
Center
  -> Worker-US
  -> Worker-HK
  -> Worker-JP
  -> Worker-EU
```

每个 Worker 使用自己的：

- `WORKER_NODE_NAME`
- `WORKER_API_URL`
- 本地文件目录
- rclone 配置

所有 Worker 共享：

- 同一个 Center
- 同一个 `API_TOKEN`
- 同一个目标目录语义

## 公开仓库与生产目录的区别

公开仓库只保留代码、文档和示例配置。

生产目录还会额外存在：

```text
.env
baicai-work/.env
runtime/
logs/
db-backups/
backups/
rclone.conf
scanner_cache.db
```

这些文件不应上传到 GitHub。

## 建议流程

1. 在 Center 机器 clone 仓库。
2. 配置根目录 `.env`。
3. 初始化或迁移数据库。
4. 启动 Center。
5. 在每台 Worker 机器 clone 仓库，或只复制 `baicai-work/`。
6. 配置 `baicai-work/.env`。
7. 确认 rclone remote 可用。
8. 启动 Worker。
9. 观察 Center 日志和 Worker 日志。
